# Задача: инициализация frontend-проекта на Vue.js

Создай базовую архитектуру frontend-приложения для каталога домашней библиотеки.

## 1. Технологический стек

Используй:
- Vue 3 с Composition API и `<script setup>`.
- TypeScript со строгой типизацией (`strict: true`).
- Vite для сборки и запуска проекта.
- Pinia для управления глобальным состоянием.
- Vue Router для маршрутизации.
- Axios для HTTP-запросов к backend API.
- ESLint для проверки кода.
- Prettier для форматирования кода.

Используй актуальные стабильные совместимые версии библиотек.

## 2. Инициализация проекта

Если проект ещё не создан, инициализируй Vue 3 + TypeScript проект с помощью Vite.

Если проект уже существует, сначала изучи его структуру и текущие зависимости. Не перезаписывай существующие файлы без необходимости.

Установи необходимые зависимости и проверь, что проект запускается.

## 3. Структура проекта

Организуй код следующим образом:

src/
├── api/
│   ├── http.ts
│   └── storageLocations.api.ts
├── assets/
├── components/
├── layouts/
├── router/
│   └── index.ts
├── stores/
│   └── storageLocations.store.ts
├── types/
│   └── storageLocation.ts
├── views/
│   ├── HomeView.vue
│   └── StorageLocationsView.vue
├── App.vue
└── main.ts

Допускается небольшое изменение структуры, если оно обосновано архитектурно.

## 4. Настройка API

Создай единый экземпляр Axios в `src/api/http.ts`.

Требования:
- Базовый URL получать из переменной окружения `VITE_API_BASE_URL`.
- Создать файл `.env.example` с примером настройки URL.
- Настроить заголовок Content-Type для JSON-запросов.
- Настроить обработку HTTP-ошибок.
- Не дублировать конфигурацию Axios в отдельных API-модулях.
- Не хранить секреты и приватные ключи во frontend-коде.

В `src/api/storageLocations.api.ts` реализуй типизированные методы:

- `getStorageLocations()` — GET /api/storage-locations
- `getStorageLocationById(id)` — GET /api/storage-locations/:id
- `createStorageLocation(data)` — POST /api/storage-locations
- `updateStorageLocation(id, data)` — PUT /api/storage-locations/:id
- `deleteStorageLocation(id)` — DELETE /api/storage-locations/:id
- `getBooksByStorageLocationId(id)` — GET /api/storage-locations/:id/books

Используй TypeScript-типы для параметров и возвращаемых значений. Не используй `any`.

## 5. Типы данных

Создай типы и интерфейсы для места хранения книг.

Предусмотри:
- `StorageLocation` — место хранения с идентификатором, названием, описанием, расположением и изображением.
- `CreateStorageLocationDto` — данные для создания места хранения.
- `UpdateStorageLocationDto` — данные для обновления места хранения.
- Тип для книги, если он нужен для типизации ответа списка книг.

Сначала проверь, существуют ли уже модели или DTO в проекте. Если backend ещё не реализован, используй предварительные типы и явно отметь, что их необходимо согласовать с реальным API.

Учти, что изображение может передаваться как URL или как файл. Не реализуй загрузку файлов через JSON: если backend использует Multer, подготовь отдельный метод отправки `FormData`.

## 6. Pinia

Создай `storageLocations.store.ts`.

Store должен:
- Хранить список мест хранения.
- Хранить выбранное место хранения, если это необходимо.
- Иметь состояние загрузки (`isLoading`).
- Хранить сообщение об ошибке.
- Реализовать действия для загрузки, создания, обновления и удаления мест хранения.
- Обновлять состояние после успешных запросов.
- Обрабатывать ошибки без потери исходного состояния.
- Не дублировать HTTP-логику, которая уже находится в API-модуле.

Используй Composition API для создания store, если это упрощает поддержку проекта.

## 7. Vue Router

Настрой маршруты:
- `/` — главная страница.
- `/storage-locations` — список мест хранения.
- `/storage-locations/:id` — страница конкретного места хранения.

Используй именованные маршруты и соответствующие компоненты представлений.

## 8. Демонстрационный интерфейс

Создай страницу `StorageLocationsView.vue`, которая:
- При открытии загружает места хранения через Pinia.
- Отображает состояние загрузки.
- Показывает понятное сообщение при ошибке.
- Отображает карточки мест хранения при успешной загрузке.
- Показывает сообщение, если список пуст.
- Содержит кнопку повторной загрузки при ошибке.

Не используй фиктивные данные в качестве постоянного источника данных. Если backend пока недоступен, интерфейс должен корректно отображать ошибку.

## 9. Переменные окружения и запуск

Подготовь:
- `.env.example`
- корректные npm-скрипты для разработки, сборки, проверки типов и линтинга.

Не добавляй реальные секреты в `.env.example`.

## 10. Требования к качеству

- Используй строгую типизацию TypeScript.
- Не используй `any` без веской причины.
- Разделяй API-запросы, состояние и UI.
- Не помещай HTTP-запросы непосредственно в компоненты представлений.
- Не создавай избыточные абстракции и ненужные слои.
- Соблюдай единый стиль именования файлов, типов и функций.
- Не устанавливай дополнительные библиотеки без необходимости.

## 11. Порядок выполнения

1. Изучи текущее состояние проекта.
2. Определи, какие зависимости и файлы нужны.
3. Инициализируй проект и установи зависимости.
4. Создай конфигурацию API, типы, store и маршруты.
5. Создай демонстрационную страницу.
6. Запусти доступные проверки TypeScript, ESLint и production-сборки.
7. Исправь обнаруженные ошибки.
8. В конце кратко объясни структуру проекта, назначение созданных файлов, команды запуска и то, что потребуется согласовать с backend.

Выполняй изменения непосредственно в проекте. Не ограничивайся выдачей примеров кода в чате.
